# Flatpak packaging

How to build and run Scriptura's Flatpak locally. The manifest lives at the
repo root as `io.github.andresmessina_SDG.Scriptura.yml`.

Related, and deliberately separate:

| File | What it covers |
|---|---|
| `STATUS.md` (this directory) | what the package contains, what is verified, what was ruled out |
| `SWORD-PYTHON-BUILD.md` (this directory) | how SWORD's Python bindings actually build — read before touching that area |
| `FLATPAK_RELEASE.md` (repo root, gitignored) | signing, publishing and the release procedure |

## What is in this directory

- `patches/sword-curl-libraries.patch` — applied to `libsword`; the CMake
  build does not propagate curl.
- `README.md`, `STATUS.md`, `SWORD-PYTHON-BUILD.md` — the docs above.
- `scriptura.sh` — **unreferenced.** Nothing in the manifest, meson or any
  doc points at it, and it is not how the app launches. The real entry point
  is generated by meson from `scriptura.in` at the repo root into
  `/app/bin/io.github.andresmessina_SDG.Scriptura`, and it is a Python shim
  (`sys.path.insert` then `from main import main`), not a shell `exec`. Left
  in place rather than removed unasked; it is a deletion candidate.

## Prerequisites

```sh
# Fedora
sudo dnf install flatpak flatpak-builder
# Ubuntu / Debian / Zorin
sudo apt install flatpak flatpak-builder
# Arch
sudo pacman -S flatpak flatpak-builder
```

Add Flathub if you haven't, and install the runtime and SDK the manifest
pins — **50**, not whatever is newest:

```sh
flatpak remote-add --if-not-exists --user flathub \
    https://flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.gnome.Platform//50 org.gnome.Sdk//50
```

Both are needed. The SDK is not optional: `python-libsword` compiles a C++
extension against libsword and the Python development headers.

## Build + run locally

From the repo root:

```sh
flatpak-builder --user --install --force-clean flatpak-build \
    io.github.andresmessina_SDG.Scriptura.yml
flatpak run io.github.andresmessina_SDG.Scriptura
```

`--force-clean` wipes the build dir each run so mistakes don't compound. A
cold build compiles curl and libsword and takes a few minutes; later builds
reuse the cache.

To run something *inside* the built sandbox without installing it — the way
to check what actually shipped:

```sh
flatpak-builder --run flatpak-build io.github.andresmessina_SDG.Scriptura.yml \
    python3 -c "import sys; sys.path.insert(0,'/app/share/scriptura'); \
                import Sword; from _version import __version__; print(__version__)"
```

## Things that will break first, and why

- **A module you added does not exist in the Flatpak.** Meson's `py_sources`
  list in `meson.build` is a second manifest; a `.py` file missing from it is
  simply not installed, and the whole test suite still passes because tests
  run against the source tree. `tests/test_meson_manifest.py` guards the list,
  but confirm against the built sandbox with the `--run` command above.
- **The version is wrong somewhere.** It is written in three places —
  `meson.build`, `_version.py`, and the newest `<release>` in the metainfo.
  `tests/test_version_sync.py` fails if they disagree, after a 1.4.0 build
  went out to staging with the About dialog still reporting 1.3.0.
- **Screenshots vanish from the AppStream data.** `appstreamcli compose`
  fetches the URLs in the metainfo and silently drops any that 404. They
  resolve to `raw.githubusercontent.com` on `main`, so **push `main` before
  building** or you ship a release with no screenshots and no error.
- **No SWORD modules on first launch.** The sandbox has its own
  `~/.var/app/io.github.andresmessina_SDG.Scriptura/.sword/` (from
  `--persist=.sword`); your host `~/.sword/` does not carry over. The welcome
  window's "Install essentials" downloads them fresh.
- **A clean build cannot fetch libsword.** CrossWire's web server and FTP
  daemon share one host and fail together when the host does. The manifest
  carries `mirror-urls` for exactly this; if a build fails at the libsword
  source step, check whether crosswire.org is up before suspecting the build.

SWIG is no longer involved. If you find advice about `SWORD_BINDINGS=Python`
or a missing `swig` binary, it is describing the approach this package
abandoned — see the ruled-out table in `STATUS.md`.

## Distribution

Not Flathub. Scriptura ships as a self-hosted, GPG-signed ostree repo on
GitHub Pages, installed in one click from
`https://andresmessina-sdg.github.io/scriptura-flatpak/scriptura.flatpakref`.
Users need the Flathub *remote* for `org.gnome.Platform//50`, which the ref's
`RuntimeRepo` line adds automatically — a runtime dependency, not a
submission.

Building and signing a release is `FLATPAK_RELEASE.md`, not this file.
